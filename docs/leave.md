# 请假流程

工作台「请假」发起申请；指定领导在首页待办或「申请与审批 → 请假 → 待我审批」处理。审批结果在消息中心，点击「查看相关内容」进入详情。

- 在职成员申请时可选其他在职「领导」，只有一位时自动选中。超管、其他领导均不能查看或审批分派给别人的单；本人不能审批自己的单。
- 全天区间含所选首末日，指定时间采用北京时间，区间首尾相接不算重叠。已开始的时段可补提，仍须领导审批。待审批、已通过、取消待审批都占用时段。
- 待审批可以撤回，修改后新建一单。已通过且尚未开始的申请可以提交取消；取消被拒或主动撤回时，原请假恢复为已通过。已经开始的请假不批准取消。
- 原审批人不再是有效领导时，本人可更换审批人。原审批人失去详情权限，历史消息仍可读但不再提供跳转。
- 私密事由、意见、审计仅保存在云函数可访问的私有集合。通知不包含事由、诊断或意见；请假不更改周报提交要求。

部署顺序：

1. 部署更新后的 `adminData`，确保通用备份排除请假集合。按当前隔离规则创建新备份后可导出；旧备份保留。
2. 在当前项目云环境按 `deployment/leave.json` 建表和建索引，确认三个集合为 ADMINONLY。沿用既有 `teamSync` 和 `teamMessages`。
3. 部署更新后的 `memberAccess`，编译或发布小程序。无需新增角色；由团队成员管理给实际审批账号设置「领导」。
4. 使用成员和领导两个账号核验申请、拒绝、通过、撤回、取消和通知直达；用无关成员确认无法查看私密详情。

本地测试：`node --test tests/leave.test.js`。测试通过内存数据库和小程序页面桩跑流程，不写入真实云数据。
