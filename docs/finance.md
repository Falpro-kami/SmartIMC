# 财务报销

在小程序「工作台 → 财务报销」查看本人记录。可按材料费、加工费、交通费、餐饮票、网络服务使用费、论文专利费和差旅费筛选，点开记录查看报销编号、金额和当前进度。

## 学生提交

点击「提交报销」，选择类别，填写单张发票金额、开票日期和报销用途。每张发票单独提交，电子发票仅收 PDF。请先把 PDF 保存到微信聊天，再点页面底部的「上传 PDF 发票」选取。补充材料按表单要求选择，每份不超过 8 MB，每笔最多 12 份且总计不超过 16 MB。填完后点击底部的「提交申请」。

上传后按类别和金额命名，例如 `材料费_500.00元.pdf`。同笔申请的补充材料加上材料类型，例如 `材料费_500.00元_支付记录.png`。提交成功后收到站内回执，列表显示「等待核验」。材料、开票日期及备注都可以在详情页查看。

## 财务专员

已通过成员审核且拥有「财务管理员」角色的账号进入财务报销时，默认显示「报销管理」，也可切换到「我的报销」提交和查看本人申请。报销管理按北京时间周一至周日的提交或登记时间归类，默认显示本周，并按报销人分组。可以查看每笔申请的材料提交情况、办理状态和附件详情，点击「刷新」读取最新进度。

在「报销管理」打开某笔申请，选择「更新报销进度」中的实际状态，再点击「保存进度」。可直接登记实际到达的阶段，也可更正误录。登记「已到账」前须确认同学已收到款项。保存后申请人会收到站内消息，可打开该申请查看进度。后续导出的汇总表会使用更新后的状态。

教学周从 2026-08-31 起算。2026-11-09 至 2026-11-15 为第十一周，2026-11-16 至 2026-11-22 为第十二周。本学期编号暂沿用团队排班至 2027-01-31，其他日期按周的日期范围显示。后续学期可在 `cloudfunctions/finance/service.js` 的 `teachingTerms` 中添加起止日期。

「导出所选周 ZIP」打包所选周所有申请的已上传附件，「导出此人 ZIP」只打包该周该同学的材料。两个操作都包含申请明细和按人汇总的 Excel，文件名包含教学周和周一日期，例如 `第十一周_2026-11-09_全部成员_报销材料.zip`。手工登记且无附件的申请也会列在汇总表中。每次导出最多 200 笔、附件合计最多 64 MB。

## 手动登记和更新

在微信开发者工具的「云开发 → 数据库 → 高级操作 → + → add 模板」登记记录。将模板中的集合改为 `financeClaims`，把 `data` 数组中的示例替换成一条按下表填写的报销记录，再点击「执行」。确认预览只新增一条记录后提交。普通「添加记录」表单限制自定义文档 ID 长度，登记时用高级操作填写完整的 `_id`。核对 `ownerId` 对应报销人的小程序成员 ID 后再提交。

| 字段 | 填写方式 |
| --- | --- |
| _id | fc_ 后接 32 位小写十六进制字符。每笔报销使用不同 ID |
| teamId | IMC |
| ownerId | 对应成员在 teamMembers 集合里的 user_ 开头的 ID |
| number | 你登记的报销单编号，例如第九周-1 |
| category | 上述七个类别之一 |
| amount | 报销金额，单位为元，字段类型为数字 |
| status | 等待核验、已核验、已制单、已签字、已提交财务处、已到账 |
| createdMs | 登记时间的 Unix 毫秒值，字段类型为数字，用于列表排序 |
| updatedAt | 可选的进度更新时间，可填 YYYY-MM-DD HH:mm |
| description | 可选的报销说明 |

后续只需在原记录修改 status，并按需更新 updatedAt。学生重新打开页面或下拉刷新后即可看到进度。已到账应在学生确认收款后登记。历史记录中的数字 stage 和以分计的 cents 仍可读取。

## 云环境

在小程序配置的云环境部署 `finance` 云函数。按 `cloudbaserc.json` 设置 60 秒超时，给文件校验及保存留出时间。`financeClaims` 和 `financeFiles` 的权限均为「所有用户不可读写」。`financeClaims` 添加非唯一索引 `finance_by_owner`，字段依次为 `teamId` 升序、`ownerId` 升序、`createdMs` 降序、`_id` 降序。确认云存储为「仅创建者可读写」且项目已有 `teamMessages`、`teamSync/IMC`。当前团队云环境使用现有桶，其他环境通过 `FINANCE_STORAGE_PREFIX` 设置该环境的 `cloud://环境ID.桶名/`。

财务专员端还需要将 `financeArchives` 和 `financeAudit` 集合设置为「所有用户不可读写」，并在 `financeClaims` 添加非唯一索引 `finance_by_team`，字段依次为 `teamId` 升序、`createdMs` 降序、`_id` 降序。部署云函数时安装依赖，并按 `cloudbaserc.json` 为 ZIP 打包配置 512 MB 内存。ZIP 和附件由云函数核验调用者权限后下载。

临时上传路径为 `finance-uploads/`，云函数校验通过后将文件保存至 `finance-files/`，并尝试删除临时件。已提交材料通过云函数验证申请归属后读取。运营人员可在云控制台根据 `financeClaims.files` 中的文件 ID 查找附件，并继续手动维护进度。

安装 finance 目录的依赖后，可运行 `node --test tests/finance.test.js` 验证 PDF 提交、角色隔离、周次归类、按人导出、ZIP 内容和手动状态更新。
