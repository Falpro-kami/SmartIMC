# 每周分享

代码在 `ysy` 分支中开发。每周一至周日为一个值班周期，所有日期与提醒边界均使用北京时间。每周两名负责人共同完成一份分享，任一人首次提交后进入同一审批流程。

初始排班来自用户提供的工作簿，包含2026年10月26日至2027年1月31日的连续14周。来源、工作表行号与原文件 SHA-256 保存在 `cloudfunctions/weeklySharing/roster-source.json`。表内未写年份，按当前学期推定为2026—2027年，并校验每周均为周一至周日。

## 成员权限

| 身份 | 值班表 | 上传内容 | 审批前查看内容 | 审批 | 审批通过后查看 |
| --- | --- | --- | --- | --- | --- |
| 高创，绑定 `sharing_reviewer` 角色 | 设置、调整和查看全部任务 | 本人值班时可上传 | 可以 | 通过或驳回 | 可以 |
| 当周负责人 | 本周、下周及本人所有周次 | 可以，驳回后可重新提交 | 仅本人上传的内容 | 无 | 可以 |
| 其他已审核团队成员 | 本周、下周及本人所有周次 | 无 | 无 | 无 | 可以 |

值班表仅由高创维护，服务端固定绑定已核实的高创成员账号 `user_1db996e0b87233a509a73b4bd6434874`，并要求其具备“分享审批人（高创）”角色。姓名变化不会授予其他人权限，超级管理员也不能将该角色分配给其他账号。`teamSecurity/IMC.sharingReviewerId` 记录这一绑定。

高创保留原有学术管理员角色，并单独绑定分享审批角色。其他账号的超级管理员或学术管理员身份不能授予分享维护和审批权限。角色变更沿用现有成员审计与实时刷新机制。

界面采用日历排班方案，主标题为“值班安排”。月历按北京时间从周一开始显示42天，支持切换月份、点选某周和查看全部记录；日历与列表使用相同的服务端权限范围。高创可看全部，其他成员（含超级管理员）仅可查看本周、下周以及本人被安排的周次，筛选发生在数据库分页之前，指定月份、周次或直接任务链接均不能绕过。

“值班任务”详情不显示顶部日期区间，所有界面不展示首次提醒时间和周三截止更新说明。默认提醒时间与后台提醒流程保留。审批通过的文件仍可通过内容链接供团队成员读取；范围之外的公开内容响应不返回负责人、排班日期或提醒时间。

## 值班与审批

任务状态：待完成、已完成、未完成。内容状态单独记录：待上传、待审批、已通过、需修改。

- 周结束前尚未审批通过：待完成。
- 审批通过：已完成，内容向已审核团队成员公开。
- 周结束仍未审批通过：未完成，同时保留“待审批”或“需修改”等内容状态。
- 两名负责人共同收到提醒；任何一人首次提交后，该周只能保留同一份提交。并发提交仅首份成功，避免互相覆盖。
- 审批通过前，搭档也不能查看实际上传人的私密文件。驳回后由原上传人修改、重新提交，并重新审批。
- 已通过内容固定，不允许上传人覆盖已公开文件；已提交过内容的任务不能更换负责人。
- 支持过周补交。审批通过后状态更新为已完成，提交与审批时间保留。
- 高创可调整尚未提交内容的历史排班，绑定真实负责人后安排补交。已经发出的逾期提醒不会因调整排班重复发送。
- 已结束且未提交或需修改的任务可由高创归档，保留“未完成”记录，从首页待办和值班表默认列表移除，停止提醒；通过“已归档”筛选可查看，并能恢复跟进。待审批任务须先完成审批，已通过任务不允许归档为未完成。

上传支持 PDF、Word、PPT、Excel，最多5个文件，单个20MB、合计50MB。服务器校验文件格式、大小和归属，将文件复制到服务端专用目录。客户端只取得文件元数据；读取时分块经过云函数重新验证成员身份与当前审批状态，不返回云文件 ID 或临时下载地址。

高创可从“导入提供的 Excel 排班”预览并初始化排班。已存在的周次会跳过，提交过的内容不会被覆盖。尚未加入团队的排班人员保留姓名并标记“账号待绑定”，不能据姓名获得上传权限；加入团队后由高创在“调整值班安排”中选择真实账号。历史周次导入时不会集中补发过期提醒。

## 提醒与入口

首页“团队动态”使用自动轮播，每5秒切换，支持手动滑动；离开首页暂停，返回后继续。分享负责人在上传内容时填写分享主题并上传 JPG/PNG 封面（最大2MB，建议横向图片），封面与文件一并提交高创审批。首页只读取最近四周已通过审批且未归档的分享，标题直接使用负责人填写的主题；未审批、被驳回的主题与封面不会进入首页。老数据无封面时使用本地默认图；无已通过分享时显示准备中的空态。点击分享可直接查看已审批内容，不扩大排班可见范围。

封面沿用私有存储和逐块鉴权下载，不返回云文件 ID 或临时地址；上传校验实际图片格式、大小、尺寸、所属任务与上传人。成员权限撤销后停止读取，离开首页清理本地封面。新提交必须包含封面，旧的已审批记录无需补改。

AI挑战赛当前使用本地示意图片，明确标注“赛事预览 / 示意图片”，可进入现有挑战赛入口；没有虚构正在进行的赛事、举办人或报名信息。赛事模块接入后，应由举办人上传标题和封面，首页仅返回已发布且正在进行的赛事。占位配置在 `miniprogram/services/home-previews.js`，本地示意图可通过 `scripts/generate-home-previews.py` 重新生成。

目前提醒接入项目消息中心。不是微信订阅消息，关闭小程序时不会产生微信通知。

| 时机 | 条件 | 接收人 |
| --- | --- | --- |
| 周一默认09:00，界面不显示提醒时间 | 尚未有效提交 | 当周负责人 |
| 周三24:00，即周四00:00 | 尚未提交或被驳回后尚未重新提交 | 当周负责人 |
| 下周一00:00 | 当周尚未有效提交 | 高创 |
| 提交内容 | 新提交版本进入待审批 | 高创 |
| 审批通过或驳回 | 完成审批 | 上传人 |

已上传并等待审批的任务不会被误报为“尚未更新”。周结束时若仍待审批，任务显示“未完成 · 待审批”，原审批通知与待办继续保留。

`weekly-sharing-reminders` 定时触发器每5分钟扫描到期任务，因此正常通知延迟不超过一个扫描周期。使用服务端时间判断业务边界，不依赖浏览页面触发。通知 ID 固定，发送标记与消息在同一事务中提交；重复调度不会重复发消息，停机后会补发当前阶段提醒，不集中补发过期阶段。

定时入口根据服务端提供的成员身份区分客户端调用：带 OPENID 的调用始终走成员鉴权，不能用伪造的定时事件启动任务。后台触发可保留应用标识 APPID。最近一次执行开始、结束、处理数量或失败错误码保存在私有 `sharingAudit/weekly-sharing-reminders` 中；仅高创可通过 `weeklySharing` 的 `status` 操作读取触发器与执行摘要。

工作台“每周分享”进入值班表；首页“我的待办”显示尚未归档的本人值班与高创待处理任务；“申请与审批”新增“每周分享”分类，显示我的申请、待我审批、我已审批。消息可直接跳转任务详情。

## 部署

本地代码和测试不代表云端已生效。项目当前云环境为 `well-leopon-d5glrufc6e4fd4413`。初始化流程由高创账号调用 `weeklySharing` 的 `initialize` 操作，创建私有集合、补充缺失索引、合并存储权限及创建提醒定时器；其他存储路径的既有规则会保留。按以下顺序完成部署：

1. 创建 `sharingTasks`、`sharingFiles`、`sharingAudit` 三个集合，均设为 **仅管理员可读写 / ADMINONLY**。禁止小程序直接读取未审批文件或提交记录。索引建议见 `deployment/weekly-sharing.json`，也可根据云控制台的索引提示补充组合索引。
2. 云存储已有 `PRIVATE`（仅创建者及管理员可读写）时直接沿用：临时上传属于上传人，定稿为服务端创建的私有副本，成员通过经鉴权的云函数读取。该方式不要求套餐支持自定义规则。其他权限模式下，初始化会保留原有路径规则，并为 `sharing-files/` 添加客户端禁止读写、为 `sharing-uploads/` 添加仅创建者上传的限制；自定义规则不可用时会报出具体失败步骤，不能当作初始化成功。
3. 上传并部署 `weeklySharing` 和更新后的 `memberAccess` 云函数，选择“云端安装依赖”。新云函数使用现有项目同版本的 `wx-server-sdk`。其他云函数的 `access.js` 也同步了角色定义，后续部署时一起更新。
4. 为 `weeklySharing` 创建定时触发器：名称 `weekly-sharing-reminders`，表达式 `0 */5 * * * * *`。定义已同时写入 `cloudbaserc.json` 和 `cloudfunctions/weeklySharing/config.json`。
5. 为上述已核实的高创账号授予“分享审批人（高创）”角色。保留其原有学术管理员角色，并记录成员审计、递增成员版本、刷新 `teamSync` 游标。
6. 使用高创登录的小程序调用 `weeklySharing` 的 `initialize`，核实集合为 ADMINONLY、文件规则生效、定时器存在。随后预览 `roster` 并以返回的 SHA-256 调用 `importRoster`，或通过页面进行排班导入。
7. 模拟器刷新后核实值班表、本周双人排班、维护权限及错误提示；上传小程序正式版本需要另行执行发布流程。

云存储规则示例：

```json
{
  "read": "auth != null && !/^sharing-files\\//.test(resource.path) && resource.openid == auth.openid",
  "write": "auth != null && !/^sharing-files\\//.test(resource.path) && resource.openid == auth.openid"
}
```

云端管理 SDK 仍可访问服务端文件，小程序使用经鉴权的云函数传输。规则含义参见 [CloudBase 云存储安全规则](https://docs.cloudbase.net/storage/security-rules)。不得将定稿目录设为公共可读，否则客户端鉴权无法阻止已知文件地址的直接读取。

上线核验使用真实的高创、负责人及其他成员账号：排班、上传提交、审批前隔离、通过公开、驳回重提、消息跳转、提醒触发和权限撤销。未创建集合、未配置私有存储规则、未启用定时器或未绑定账号时，不应认定线上流程已可用。
