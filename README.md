# 智慧IMC

微信原生小程序，使用 CloudBase 环境 `well-leopon-d5glrufc6e4fd4413`。

## 界面设计标准

所有页面统一采用用户于 2026-10-27 确认的「四列宫格＋分区轻卡」，后续新增功能继续沿用。[设计规范](design/visual-system.md) 保存在项目中；内部确认稿与原始素材不随公开仓库发布。颜色、圆角和间距以 `miniprogram/styles/theme.wxss` 为调色板参考；运行时 WXSS 使用明确取值和窄屏媒体规则，不依赖跨组件 CSS 变量。页面根节点保留 `imc-theme` 标记。

底部导航使用原生小程序自定义 tabBar，图标由 WXSS 绘制，避免图片资源加载失败。保留首页、工作台、我的，页面仍通过 `wx.switchTab` 切换；各页面 `onShow` 同步选中状态，页面底部预留安全区。

## 用户资料和工作台

所有页面统一执行入组检查，包括分享链接和直接进入的二级页面。新用户首先显示不可跳过的加入 IMC 申请表，填写姓名、主动选择头像（可选）并提交；提交只生成待审核申请，不授予任何业务权限。待审核只能看到等待审核及查询审核结果，只有服务器确认 `IMC + active` 才展示业务页面和底部导航。校验失败、停用、移出及其他团队身份均保持拦截。首次进入验证一次，本次运行期间切页复用已由服务端确认的身份，不重新展示验证页或重复请求身份；身份仅保存在内存中，重新启动后重新验证。手动查询审核结果、身份变更及现有消息轮询可刷新状态，业务接口始终在服务端检查当前权限。

入组前仅开放必要的本人资料提交、入组申请和本人审核状态查询；消息、申请与审批记录、常用应用统计、成员目录、设备、公告、云服务检测及管理接口均在服务端拒绝未审核身份。页面加载由 `utils/member-page.js` 统一延迟到审核通过后，全局 `membership-gate` 组件显示强制申请/等待状态；验证期间不渲染业务组件。既有成员被停用或移出后，页头身份复核会重新锁定当前页面。

首页、工作台和「我的」左上角统一显示头像、姓名、团队名称。点击头像打开左侧团队栏，提供「查看团队成员」，仅通过审核且启用的 IMC 成员可读取；未加入、待审核、停用和其他团队账号均由服务端拒绝。目录只展示已加入且启用的 IMC 成员姓名、头像和角色，不返回权限明细、审核记录或管理操作；头像通过服务端临时链接显示，头像失败使用文字占位。

三个主页面的共用页头整体吸顶，包含状态栏安全区、页面标题、个人身份与消息入口；下方业务内容滚动时，页头保持可见。页头按角色标签与错误状态自然撑高，不采用固定高度占位，避免多角色换行后遮挡首项业务内容。

首页包含「我的待办」「团队公告」两个分区轻卡。待办当前展示本人有权处理的成员入组申请，最多5条，点击直接处理，「全部」进入申请与审批的「待我审批」。处理后返回首页重新读取，不改变通知已读状态；尚未接入的周报、请假、报销等业务不会生成虚构待办。

团队公告首页预览3条，置顶优先，其后按发布时间排序；「全部」打开复用模块页中的公告列表和正文。已审核且启用的成员可查看，超级管理员可发布、编辑、置顶和撤下文字公告。标题1至80字，正文1至10000字，正文按纯文本显示并保留换行；此阶段不包含附件上传、公告已读统计或微信推送。并发修改校验版本，撤下保留原记录但停止向成员展示。新环境先运行 `node scripts/setup-announcements.cjs` 创建私有集合 `teamAnnouncements` 及列表排序索引，公告随业务数据自动纳入已有备份。

个人资料编辑统一放在「我的 → 个人资料」，可以选择微信头像、填写和修改姓名。微信身份自动识别，保存后同步更新页头，重新进入自动恢复，无需账号密码。

「我的」框架包括个人资料、我的事务、团队成员、成员与权限、数据与服务及设置与帮助。身份仅在头像旁显示，不重复展示成员身份卡片。我的事务保留「我的设备、我的提交、我的收藏」入口；设置与帮助包含「隐私与授权、意见反馈、账号与数据、关于智慧IMC」，菜单复用已注册的 `pages/module/index?id=settings`，不依赖单独新增的设置页模板。具体业务入口目前仅打开对应标题的筹备页面，尚未实现业务记录、收藏、反馈提交、隐私授权或账号注销等操作。已有资料编辑、申请加入 IMC、成员目录及超级管理员权限管理继续使用原功能。申请与审批仍统一从工作台进入，不在「我的」重复设置申请入口。

团队成员列表末尾提供「邀请成员」分享入口，作为最后一行随成员列表排列。使用微信原生 `button open-type="share"`、`Page.onShareAppMessage` 和 `wx.showShareMenu({ menus: ['shareAppMessage'] })`，用户点击按钮后由微信打开联系人选择页，选择好友后发送邀请卡片。卡片进入「我的」页面，受邀者可填写资料并申请加入 IMC。分享不会直接加入团队或授予角色，仍由超级管理员审核；分享动作由用户在微信内完成，未实现自定义好友列表或代发消息。

页头 IMC 下方显示当前角色的不同颜色标签，多个身份同时展示；右侧铃铛进入消息列表，右上角显示本人未读数量：1至99条显示数字，100条起显示「99+」，没有未读时隐藏。首页、工作台和我的共用该页头及未读状态，切换页面复用会话，消息变化通过实时同步更新。

`teamMessages` 为站内消息，权限为 `ADMINONLY`，由 `memberAccess` 读取与标记已读。新成员申请生成超级管理员可见的共享消息，每位管理员的已读状态独立保存。角标只表示未读：打开消息或处理申请均不自动清除，必须点击「标记已读」；申请处理后另显示「已处理」。审核结果、角色和成员状态变更通知对应用户；申请、审批、审计与消息写入同一事务，失败时一起回滚。消息接口服务端判断收件人和当前管理权限，客户端不能指定其他收件人；角标查询最多读取100个未读消息ID，独立于消息列表分页。上线此功能前运行 `node scripts/setup-messages.cjs` 建立集合并补齐现有待审核申请，脚本不会重置已读状态。此功能为小程序内消息，未接入微信订阅消息。

头像采用微信 `chooseAvatar` 选择能力，需用户主动点选，不能静默读取微信头像。未选择头像时显示姓名文字头像；已选择的头像上传至云存储，避免临时路径过期。资料失败时允许重试，姓名和头像通过 `userProfile` 云函数按当前用户独立保存到 `userProfiles` 集合，数据库为 `ADMINONLY`。服务端不接受客户端指定其他用户或角色。

团队名称固定为大写 `IMC`，由配置文件 `miniprogram/config/team.js` 统一提供。首次入组在强制申请界面完成，等待超级管理员审核；填写姓名和成功提交申请都不代表已经获得团队业务访问权限。

## 成员与权限

数据权限核查、独立加密备份、密码/密钥保管及恢复演练见 [数据保护与恢复](design/data-protection.md)。小程序提供仅超级管理员可用的手动数据备份与导出，电脑管理脚本作为补充。

超级管理员可在「我的 → 数据与服务」手动创建、下载并导出加密数据备份，查看云服务真实到期信息。`adminData` 每次请求验证当前超级管理员身份；普通成员及其他管理角色不可使用。到期日期来自腾讯云 `DescribeBillingInfo`，不是写死的倒计时。备份记录 `adminBackups` 保持 `ADMINONLY`，导出文件保持私有；新环境部署前运行 `node scripts/setup-admin-data.cjs`。原 Codex 每日任务已删除，不使用外部定时任务。

页头头像旁显示当前角色。只有启用中的超级管理员会看到「成员与权限」，可以审核申请、分配多个角色、停用及恢复成员。没有管理角色的已加入成员就是普通成员。所有已审核成员均可查看成员目录，查看不会授予修改权限。

超级管理员还可在成员编辑弹窗点击「移出成员」，原生确认后移出。服务端将其状态改为 `removed`、清空角色并保留历史数据与审计；已移出的账号不再出现在成员目录和管理列表。再次打开小程序会显示「重新申请加入 IMC」，沿用本人姓名和头像，可主动重新提交；重新申请只改为 `pending`、清空角色并增加版本，仍需超级管理员审核，不能自行恢复访问或旧管理角色。每次重新申请使用新的申请消息和审批关联，旧通知的已读状态、旧审批结果与历史业务记录保留。停用账号仍需管理员处理，不能通过重新申请绕过停用。最后一名启用的超级管理员不能被移出。移出、重新申请及各自的通知和审计均使用事务，任何一步失败均回滚。

固定角色为：领导、学术管理员、5S管理员、财务管理员、周报管理员、超级管理员。5S管理员对应设备登记、维护、使用审批等权限；其余业务管理员只拥有各自模块的管理权限。领导具有团队周报及学术汇总查看权限。超级管理员通过服务端 `*` 权限拥有全部业务和成员管理权限，包括后续接入此权限体系的操作。

当前阶段完成权限分配基础和现有设备查询的成员准入；设备登记、使用申请审批、周报上传等具体业务尚待实现，声明权限不代表这些业务已经可操作。

- `userProfiles` 仅保存个人资料；`teamMembers` 独立保存 IMC 成员状态、角色和权限版本，改姓名/头像不会更改角色。
- 新申请一律为 `pending`、无管理角色；停用后再次申请不会覆盖原记录或恢复权限。
- `equipmentQuery` 服务端检查当前成员是否启用，待审核、未加入、停用账号不能读取设备数据。
- `memberAccess` 只信任 `getWXContext` 的微信身份。修改权限的事务内再次验证授权，校验权限版本并写入 `memberAudit`；`teamSecurity` 同步维护超级管理员名单，阻止撤销或停用最后一名超级管理员。
- 三个权限集合及日志均设为 `ADMINONLY`。客户端不直接读写角色。权限更新影响后续服务端请求，已下载到设备上的数据不具备远程擦除能力。
- 首名超级管理员通过受信管理端初始化，公开接口不提供「抢占首位管理员」功能。初始化脚本必须传入人工确认的账号识别码和姓名，已有其他成员时会停止。

公共权限策略在 `cloudfunctions/_shared/access.js`，部署相关函数前运行 `node scripts/sync-access.cjs`，同步到独立云函数包。新业务接口须调用该策略检查具体操作权限及操作对象归属，不能仅依靠页面按钮显示。

工作台分为上方「常用应用」和下方「全部应用」。全部应用保留固定顺序，包括单行显示的「实验室设备」、财务报销、周报、文娱活动、AI挑战赛、「申请与审批」、请假、团队知识库及每周分享。常用应用显示前 4 项，按当前微信用户成功打开应用的累计次数排序，同次数按最近打开时间，再按默认顺序排序；没有记录时按默认顺序。数据在 `workbenchUsage` 集合按服务端微信身份独立保存，权限为 `ADMINONLY`，换设备可恢复。统计失败不会阻止打开应用，导航失败不计数。部署前运行 `node scripts/setup-workbench.cjs` 建立集合。

「申请与审批」包含「我的申请、待我审批、我已审批」，目前接入成员入组申请。本人可查看自己的申请及结果；超级管理员可以处理待审批事项，并查看本人实际处理的记录，普通成员无法读取他人的成员审批记录。办理审批不会改变消息的未读状态。财务报销、周报、文娱活动、AI挑战赛、请假、团队知识库、每周分享七个业务入口仍为筹备页面，业务表单和办理流程待后续定义。

## 在另一台电脑协作开发

1. 安装 Git、Node.js 20 或以上版本及微信开发者工具，使用已被添加为本小程序开发者的微信登录。
2. 克隆仓库：`git clone https://github.com/Falpro-kami/SmartIMC.git`。
3. 在微信开发者工具导入克隆后的项目根目录（包含 `project.config.json`），AppID 为 `wx875c04f31134c779`。不要只导入 `miniprogram` 子目录。
4. 编译后可使用已部署的云函数。开发者登录产生自己的微信身份，小程序成员审核与业务角色仍需独立分配，不会因拥有源码而自动获得业务权限。
5. 修改云函数时，在对应函数目录安装依赖；需要部署或管理云资源时，使用本人获授权的 CloudBase 账号登录官方工具，不复制他人的凭据。按分工授予云端管理权限。
6. 每次开发先拉取最新提交，使用自己的功能分支并通过 Pull Request 合并；上传体验版前先同步并验证，避免不同电脑互相覆盖。

仓库不包含线上数据库、云文件、真实设备源表、备份文件、密码、密钥或本机私有配置；克隆不会复制这些数据。内部设计参考图和 Word 素材另行保管。环境 ID 与 AppID 用于关联项目，不是访问凭据，实际访问仍由微信身份和云端权限校验。

## 设备管理第一版

在微信开发者工具中导入本目录，编译后进入「工作台 → 实验室设备」。

- 搜索框与筛选之间提供浏览方式图标，点击选择「卡片显示／表格显示」，默认卡片，并记住本机上次选择。切换保留当前搜索、筛选和已加载记录。
- 卡片上方显示名称、编号、设备图片框和状态，下方并排显示型号、设备位置、使用人。表格显示名称、编号、设备位置、使用情况；两种显示均可点击进入详情。
- 页面采用白底、细分隔线，移除设备总量及状态统计选项卡。使用情况和设备位置统一通过搜索旁的「筛选」选择，不显示建账分类。
- 设备信息空值统一显示 `-`；设备编号仍保留前导零。
- 搜索名称、资产编号、台账流水号、型号、使用人、责任人和存放地。

首版提供设备查询，不含新增、修改、删除、借还和出入库。当前数据来自用户提供的 Excel，尚未接入 Gitee 自动同步。原表没有设备照片，卡片保留图片框并显示占位；记录的 `image` 字段有图片地址时，卡片与详情会显示该图片，加载失败则回退至占位。尚未提供上传照片入口。

## 数据和云端部署

`equipment` 集合保存设备数据。数据库权限为 `ADMINONLY`，小程序通过 `equipmentQuery` 云函数只读查询，不在前端放云密钥或完整设备清单。

云函数只接受本小程序 AppID 的微信用户调用；身份通过 `cloud.getWXContext()` 获取，不信任请求内传入的身份。设备数据仅向审核通过且未停用的 IMC 成员提供。部署开发环境不等于已发布小程序。

### 小程序与已有云环境的关联

腾讯云侧创建的环境需要先完成账号关联，再在微信开发者工具里转换为可供小程序使用的环境。仅有环境 ID 和成功的管理端数据库查询，不能证明小程序端已经可调用。

1. 在现有环境所属腾讯云主账号的「账号中心 → 登录方式 → 微信公众平台」关联当前小程序，核对 AppID 为 `wx875c04f31134c779`。
2. 微信开发者工具顶部「云开发 → 设置 → 环境名称下拉 → 管理我的环境 → 使用已有腾讯云环境」。
3. 选择 `well-leopon-d5glrufc6e4fd4413`，由小程序管理员扫码确认环境转换。
4. 重新编译，再打开设备管理验证。

具体入口以当前控制台为准，见 [CloudBase 官方关联与环境转换说明](https://docs.cloudbase.net/quick-start/create-env)。

`-601034`「没有权限，请先开通云开发或者云托管」是在微信侧进入云函数前被拒绝，应检查上述开通和关联流程。函数内部的 `AUTH_REQUIRED` 以及数据库权限属于其他校验层，放宽它们无法解决此错误。

## 周报（自定义表单与文件）

工作台「周报」支持管理员自定义表单模板。字段类型为文本、数字、日期、单选、多选和附件；文本统一使用微信原生富文本编辑器，支持标题、加粗、斜体、下划线、列表、对齐、撤销/重做和插入图片。图片使用 `wx.chooseMedia` 选择 JPG/PNG，Word（`.doc`、`.docx`）和 PDF 附件使用 `wx.chooseMessageFile`。编辑工具栏使用飞书参考的单行图标、标题下拉菜单、文字颜色/高亮色板与更多浮层；窄屏横向滑动，更多固定在右侧，长按查看操作名称。标题与色板操作先恢复正文选区，横向滑动不会误触格式。按用户要求不包含超链接、引用块和OKR入口。正文和附件自动保存草稿，无单独保存草稿按钮；提交完成即为已提交，不经过审批，后续修改与已提交版本分开保存。已有文件型周期继续兼容。

周报管理员、超级管理员在「表单模板」创建或编辑模板，配置分区、多级标题、字段名称和顺序、必填规则、文本字数、选项、附件数量/大小；所有字段整行排列，不提供并排设置。通过「细分标题」「添加子标题」「升一级」「降一级」组织最多6级标题，只对最深层非必填项显示勾选框，必填项直接填写；勾选叶子项自动激活所有上级标题，勾选状态与正文一起自动保存。阅读版保留全部一级标题，有已勾选且填写的内容时只显示对应分支及上级标题；未勾选或空白的同级分支隐藏，整个一级标题下均无内容时只显示该标题和一处「无」。无子标题的一级分区直接填写文本，留空为「无」。数字0及图片正常展示。一级自动编号「1.」，二级「（1）」，三级及以下用完整层级编号。最多10个一级分区、30个填写项及80个标题/字段节点，文本最多10000字及10张图片，附件字段最多5个文件、单个最多5MiB；每份周报正文图片与附件合计不超过10MiB。每个分区、标题和字段可选填最多1000字说明，有说明时紧跟填写项标题右侧显示「说明」，点击展开或收起，正式阅读版不显示说明。发布时将模板及说明快照写入周期，编辑公共模板不会自动改动已发布周期。周期设置提供独立的「编辑本期表单」，应用后返回同一设置页，最终点击「更新周期」生效，不修改公共模板。

富文本只保存经过服务端白名单校验的 Delta，不保存 HTML、客户端本地图片路径或临时签名地址。内嵌图片以业务附件 ID 引用，云函数校验字段、周期和所属人后冻结私有原件；查看时重新鉴权换取临时链接。`weeklyTemplates` 保持 `ADMINONLY`，自动纳入现有动态备份。领导的周期入口居中显示「查看团队提交」，周期设置按实际管理权限显示，兼具领导与管理员身份仍可管理；旧版被修订后隐藏设置入口。团队列表直接展示附件的查看/下载按钮，表单内容在当前列表内展开。

发布周报、周期设置、表单模板列表和模板新建/编辑分别使用独立的原生页面层级，复用已注册模块路由。返回逐级回到进入前的页面；选择模板返回原发布表单，保留已填写的标题、截止时间与名单。发布成功用详情替换发布页，返回到原周报列表；模板保存返回模板列表。

发布后的名称、日期、截止时间、应交成员、免交及逾期规则可直接更新。尚无草稿或上传记录时，表单也可原地修正；开始填写或上传后，修改任何表单字段/规则/说明需确认发布修订版。新版是关联同一根周期的新记录（第2版、第3版等），旧版停止填写、原草稿/提交/文件/统计保留，成员可查看上一版并按新版重新提交，不自动搬移或覆盖内容。旧版不能重新开放或继续派生另一修订版；列表和详情显示版次，详情提供上一版/新版入口。修订发布需将周期设为开放中，最多100版。设置实际变化时向原名单和新名单中仍启用的成员发送站内变更通知，说明变更项目，独立于原通知且不自动标记已读。草稿保存和上传携带表单指纹，拒绝旧页面向已修正表单写入。

模板编辑页右上角「预览」打开独立页面：「模板结构」显示当前未保存模板的全部标题层级与空项，并支持展开说明；「阅读效果」按正式阅读规则显示，无填写内容的一级标题下显示一处「无」。预览与正式周报使用同一阅读组件；通过原生页面通道传递本次预览数据，不写数据库、不发布周期，返回后保留编辑内容和滚动位置。

周报管理员/超级管理员可发布和修改周期、选择应交成员、填写免交原因、设置北京时间截止时间及逾期补交/修改规则，关闭或归档周期，查看提交统计、手动催交、导出 CSV 统计。领导可查看团队已提交周报；其他业务管理员不因此获得周报管理权。新加入成员由管理员加入指定周期的应交名单，历史名单不会随当前成员变化自动改写。催交通知每日幂等，处理业务不清除未读，仍需手动标记已读。首页显示本人应交且未提交的周报。

发布支持立即发布或指定北京时间定时发布；每份周期独立设置日期、时间，可更改或取消。`weeklyPublish` 按分钟扫描到期记录，事务内复核发布人的管理权限，再原子公开周期、发送一次通知并记录审计。待发布及已取消记录仅周报管理员可见，不会提前推送。触发器按分钟执行，平台延迟可能使实际发布时间稍晚；这不是每周重复创建周期的订阅任务。小程序用户伪造定时事件会被拒绝。

部署前执行 `node scripts/sync-access.cjs`、`node scripts/setup-weekly.cjs`（仅创建缺失私有集合和索引，不生成业务数据），然后部署 `weeklyReport`、`weeklyPublish` 与更新后的 `memberAccess` 云函数，并确认 `weekly-publish-minute` 触发器已启用。前端复用 `pages/module/index?id=weekly`。附件由服务端验证后另存为私有原件，读取通过已授权的记录换取临时链接；微信下载域名未配置时，自动使用逐块校验权限的云函数传输，数据库和存储规则不放宽。详见 `design/data-protection.md` 的备份容量限制。

周报列表卡片和详情提供管理员「删除」入口，确认后仅移除当前版本的列表及待办入口，停止填写及定时发布。已有草稿、提交版本和私有文件保留，已发布的历史内容按原权限只读查看；删除未发布周期不会向普通成员公开内容。删除不影响关联的其他版本，不重置原消息已读状态，并记录操作者和审计。

页面数据使用本次运行的内存缓存（普通列表30秒、工作台统计及云服务状态60秒），并合并并发请求。再次打开先显示已有内容，超时后后台更新；写入、成员身份或角色变化会使相关缓存失效，不把业务数据存到磁盘。首页和周报支持下拉强制刷新。消息未读数量独立同步到全部页头，实时连接正常时每30秒补核版本和成员状态，监听失败期间每5秒补查版本；业务处理不会代替手动标记已读。
