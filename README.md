# 智慧IMC

微信原生小程序，使用 CloudBase 环境 `well-leopon-d5glrufc6e4fd4413`。

## 界面设计标准

所有页面统一采用用户于 2026-10-27 确认的「四列宫格＋分区轻卡」，后续新增功能继续沿用。[设计规范](design/visual-system.md) 保存在项目中；内部确认稿与原始素材不随公开仓库发布。颜色、圆角和间距以 `miniprogram/styles/theme.wxss` 为调色板参考；运行时 WXSS 使用明确取值和窄屏媒体规则，不依赖跨组件 CSS 变量。页面根节点保留 `imc-theme` 标记。

底部导航使用原生小程序自定义 tabBar，图标由 WXSS 绘制，避免图片资源加载失败。保留首页、工作台、我的，页面仍通过 `wx.switchTab` 切换；各页面 `onShow` 同步选中状态，页面底部预留安全区。

## 用户资料和工作台

首页、工作台和「我的」左上角统一显示头像、姓名、团队名称。点击头像打开左侧团队栏，提供「查看团队成员」，仅通过审核且启用的 IMC 成员可读取；未加入、待审核、停用和其他团队账号均由服务端拒绝。目录只展示已加入且启用的 IMC 成员姓名、头像和角色，不返回权限明细、审核记录或管理操作；头像通过服务端临时链接显示，头像失败使用文字占位。

三个主页面的共用页头整体吸顶，包含状态栏安全区、页面标题、个人身份与消息入口；下方业务内容滚动时，页头保持可见。页头按角色标签与错误状态自然撑高，不采用固定高度占位，避免多角色换行后遮挡首项业务内容。

个人资料编辑统一放在「我的 → 个人资料」，可以选择微信头像、填写和修改姓名。微信身份自动识别，保存后同步更新页头，重新进入自动恢复，无需账号密码。

「我的」框架包括个人资料、我的事务、团队成员、成员与权限、数据与服务及设置与帮助。身份仅在头像旁显示，不重复展示成员身份卡片。我的事务保留「我的设备、我的提交、我的收藏」入口；设置与帮助包含「隐私与授权、意见反馈、账号与数据、关于智慧IMC」，菜单复用已注册的 `pages/module/index?id=settings`，不依赖单独新增的设置页模板。具体业务入口目前仅打开对应标题的筹备页面，尚未实现业务记录、收藏、反馈提交、隐私授权或账号注销等操作。已有资料编辑、申请加入 IMC、成员目录及超级管理员权限管理继续使用原功能。申请与审批仍统一从工作台进入，不在「我的」重复设置申请入口。

团队成员列表末尾提供「邀请成员」分享入口，作为最后一行随成员列表排列。使用微信原生 `button open-type="share"`、`Page.onShareAppMessage` 和 `wx.showShareMenu({ menus: ['shareAppMessage'] })`，用户点击按钮后由微信打开联系人选择页，选择好友后发送邀请卡片。卡片进入「我的」页面，受邀者可填写资料并申请加入 IMC。分享不会直接加入团队或授予角色，仍由超级管理员审核；分享动作由用户在微信内完成，未实现自定义好友列表或代发消息。

页头 IMC 下方显示当前角色的不同颜色标签，多个身份同时展示；右侧铃铛进入消息列表，未读消息显示红点。首页、工作台和我的共用该页头，显示期间每 30 秒检查身份与未读状态，返回页面时重新检查，隐藏或销毁后停止轮询。

`teamMessages` 为站内消息，权限为 `ADMINONLY`，由 `memberAccess` 读取与标记已读。新成员申请生成超级管理员可见的共享消息，每位管理员的已读状态独立保存。红点只表示未读：打开消息或处理申请均不自动清除，必须点击「标记已读」；申请处理后另显示「已处理」。审核结果、角色和成员状态变更通知对应用户；申请、审批、审计与消息写入同一事务，失败时一起回滚。消息接口服务端判断收件人和当前管理权限，客户端不能指定其他收件人。上线此功能前运行 `node scripts/setup-messages.cjs` 建立集合并补齐现有待审核申请，脚本不会重置已读状态。此功能为小程序内消息，未接入微信订阅消息。

头像采用微信 `chooseAvatar` 选择能力，需用户主动点选，不能静默读取微信头像。未选择头像时显示姓名文字头像；已选择的头像上传至云存储，避免临时路径过期。资料失败时允许重试，姓名和头像通过 `userProfile` 云函数按当前用户独立保存到 `userProfiles` 集合，数据库为 `ADMINONLY`。服务端不接受客户端指定其他用户或角色。

团队名称固定为大写 `IMC`，由配置文件 `miniprogram/config/team.js` 统一提供。完善资料后可在「我的」申请加入，等待超级管理员审核；填写姓名本身不代表通过团队身份审核。

## 成员与权限

数据权限核查、独立加密备份、密码/密钥保管及恢复演练见 [数据保护与恢复](design/data-protection.md)。小程序提供仅超级管理员可用的手动数据备份与导出，电脑管理脚本作为补充。

超级管理员可在「我的 → 数据与服务」手动创建、下载并导出加密数据备份，查看云服务真实到期信息。`adminData` 每次请求验证当前超级管理员身份；普通成员及其他管理角色不可使用。到期日期来自腾讯云 `DescribeBillingInfo`，不是写死的倒计时。备份记录 `adminBackups` 保持 `ADMINONLY`，导出文件保持私有；新环境部署前运行 `node scripts/setup-admin-data.cjs`。原 Codex 每日任务已删除，不使用外部定时任务。

页头头像旁显示当前角色。只有启用中的超级管理员会看到「成员与权限」，可以审核申请、分配多个角色、停用及恢复成员。没有管理角色的已加入成员就是普通成员。所有已审核成员均可查看成员目录，查看不会授予修改权限。

固定角色为：领导、学术管理员、5S管理员、财务管理员、周报管理员、超级管理员。5S管理员对应设备登记、维护、使用审批等权限；其余业务管理员只拥有各自模块的管理权限。领导具有团队周报及学术汇总查看权限。超级管理员通过服务端 `*` 权限拥有全部业务和成员管理权限，包括后续接入此权限体系的操作。

当前阶段完成权限分配基础和现有设备查询的成员准入；设备登记、使用申请审批、周报上传等具体业务尚待实现，声明权限不代表这些业务已经可操作。

- `userProfiles` 仅保存个人资料；`teamMembers` 独立保存 IMC 成员状态、角色和权限版本，改姓名/头像不会更改角色。
- 新申请一律为 `pending`、无管理角色；停用后再次申请不会覆盖原记录或恢复权限。
- `equipmentQuery` 服务端检查当前成员是否启用，待审核、未加入、停用账号不能读取设备数据。
- `memberAccess` 只信任 `getWXContext` 的微信身份。修改权限的事务内再次验证授权，校验权限版本并写入 `memberAudit`；`teamSecurity` 同步维护超级管理员名单，阻止撤销或停用最后一名超级管理员。
- 三个权限集合及日志均设为 `ADMINONLY`。客户端不直接读写角色。权限更新影响后续服务端请求，已下载到设备上的数据不具备远程擦除能力。
- 首名超级管理员通过受信管理端初始化，公开接口不提供「抢占首位管理员」功能。初始化脚本必须传入人工确认的账号识别码和姓名，已有其他成员时会停止。

公共权限策略在 `cloudfunctions/_shared/access.js`，部署相关函数前运行 `node scripts/sync-access.cjs`，同步到独立云函数包。新业务接口须调用该策略检查具体操作权限及操作对象归属，不能仅依靠页面按钮显示。

工作台分为上方「常用应用」和下方「全部应用」。全部应用保留固定顺序，包括单行显示的「实验室设备」、财务报销、周报、文娱活动、AI挑战赛、「申请与审批」、请假、团队知识库及每周分享。常用应用显示前 4 项，按当前微信用户成功打开应用的累计次数排序，同次数按最近打开时间，再按默认顺序排序；没有记录时按默认顺序。数据在 `workbenchUsage` 集合按服务端微信身份独立保存，权限为 `ADMINONLY`，换设备可恢复。统计失败不会阻止打开应用，导航失败不计数。部署前运行 `node scripts/setup-workbench.cjs` 建立集合。

「申请与审批」包含「我的申请、待我审批、我已审批」，目前接入成员入组申请。本人可查看自己的申请及结果；超级管理员可以处理待审批事项，并查看本人实际处理的记录，普通成员无法读取他人的成员审批记录。办理审批不会改变消息的未读状态。财务报销、周报、文娱活动、AI挑战赛、请假、团队知识库、每周分享七个业务入口仍为筹备页面，业务表单和办理流程待后续定义。

## 在另一台电脑协作开发

1. 安装 Git、Node.js 20 或以上版本及微信开发者工具，使用已被添加为本小程序开发者的微信登录。
2. 克隆仓库：`git clone https://github.com/Falpro-kami/SmartIMC.git`。
3. 在微信开发者工具导入克隆后的项目根目录（包含 `project.config.json`），AppID 为 `wx875c04f31134c779`。不要只导入 `miniprogram` 子目录。
4. 编译后可使用已部署的云函数。开发者登录产生自己的微信身份，小程序成员审核与业务角色仍需独立分配，不会因拥有源码而自动获得业务权限。
5. 修改云函数时，在对应函数目录安装依赖；需要部署或管理云资源时，使用本人获授权的 CloudBase 账号登录官方工具，不复制他人的凭据。按分工授予云端管理权限。
6. 每次开发先拉取最新提交，使用自己的功能分支并通过 Pull Request 合并；上传体验版前先同步并验证，避免不同电脑互相覆盖。

仓库不包含线上数据库、云文件、真实设备源表、备份文件、密码、密钥或本机私有配置；克隆不会复制这些数据。内部设计参考图和 Word 素材另行保管。环境 ID 与 AppID 用于关联项目，不是访问凭据，实际访问仍由微信身份和云端权限校验。

在微信开发者工具中导入本目录，编译后进入「工作台 → 实验室设备」。

- 搜索框与筛选之间提供浏览方式图标，点击选择「卡片显示／表格显示」，默认卡片，并记住本机上次选择。切换保留当前搜索、筛选和已加载记录。

- 页面采用白底、细分隔线，移除设备总量及状态统计选项卡。使用情况和设备位置统一通过搜索旁的「筛选」选择，不显示建账分类。
- 设备信息空值统一显示 `-`；设备编号仍保留前导零。
- 搜索名称、资产编号、台账流水号、型号、使用人、责任人和存放地。

## 数据和云端部署

`equipment` 集合保存设备数据。数据库权限为 `ADMINONLY`，小程序通过 `equipmentQuery` 云函数只读查询，不在前端放云密钥或完整设备清单。

云函数只接受本小程序 AppID 的微信用户调用；身份通过 `cloud.getWXContext()` 获取，不信任请求内传入的身份。设备数据仅向审核通过且未停用的 IMC 成员提供。部署开发环境不等于已发布小程序。

### 小程序与已有云环境的关联

腾讯云侧创建的环境需要先完成账号关联，再在微信开发者工具里转换为可供小程序使用的环境。仅有环境 ID 和成功的管理端数据库查询，不能证明小程序端已经可调用。

1. 在现有环境所属腾讯云主账号的「账号中心 → 登录方式 → 微信公众平台」关联当前小程序，核对 AppID 为 `wx875c04f31134c779`。
2. 微信开发者工具顶部「云开发 → 设置 → 环境名称下拉 → 管理我的环境 → 使用已有腾讯云环境」。
3. 选择 `well-leopon-d5glrufc6e4fd4413`，由小程序管理员扫码确认环境转换。
4. 重新编译，再打开设备管理验证。

具体入口以当前控制台为准，见 [CloudBase 官方关联与环境转换说明](https://docs.cloudbase.net/quick-start/create-env)。

`-601034`「没有权限，请先开通云开发或者云托管」是在微信侧进入云函数前被拒绝，应检查上述开通和关联流程。函数内部的 `AUTH_REQUIRED` 以及数据库权限属于其他校验层，放宽它们无法解决此错误。

源表包含两个工作表。导入规则：

- 仅保留「已建账-设备管理清单」的全部 128 条记录，不导入未建账工作表。
- 按用户确认，保留其中 2 条只有流水编号的记录；其他缺失字段在界面显示 `-`。
- 云端已删除原先导入的 7 条未建账设备，删除前的完整记录备份保存在 `.local/`。
- 设备编号按字符串保存，保留 `00809485` 等编号的前导零。
- 继续使用原有记录 ID，避免更换现存设备的详情地址；来源标记仅供导入核对。
- 保留源工作表、行号、文件摘要以供核对；这些来源字段不返回前端。

本地提取文件保存在 `.local/`，已加入忽略规则，不进入小程序代码包。原 Excel 保持不变。

重新提取（需要 Python 和 openpyxl）：

```powershell
python scripts/prepare-equipment.py "设备清单的完整路径.xlsx"
```

云端首次导入（需要先通过官方 CloudBase CLI 登录）：

```powershell
node scripts/import-equipment.cjs
```

脚本只允许导入空集合；已有数据时会停止，不会覆盖。再次核对已导入数据：

```powershell
node scripts/import-equipment.cjs --verify-only
```

函数定义在 `cloudbaserc.json`，部署命令：

```powershell
npx.cmd --yes --package @cloudbase/cli@3.8.9 tcb fn deploy equipmentQuery -e well-leopon-d5glrufc6e4fd4413 --install-dependency true --yes --json
```

导入脚本的 CLI 包装器默认使用本机 npm 缓存中的官方 CLI，也可通过 `TCB_CLI_PATH` 指定官方 `cli.js` 的完整路径。凭据由官方 CLI 管理，不保存到项目内。
