# IMC 数据保护与恢复

## 当前范围

- 全部业务页面使用统一入组拦截，未审核用户只能提交本人入组资料/申请及查询自身审核状态，不开放消息、审批、常用应用统计或其他业务数据。`memberAccess` 在业务分发前统一验证 `IMC + active`；数据库检测函数也验证微信身份与成员资格。客户端首次进入时向服务端验证，通过后在本次运行中复用内存身份，切页不再验证或显示拦截页；首次验证失败仍保持锁定。分享直达和二级页面遵循同一入组准入规则，业务接口每次独立检查当前成员权限。入组申请成功仍为 `pending`，不自动授予角色。

- 成员目录由云函数验证当前微信身份对应的成员记录，只有 `IMC + active` 可读；不是通过隐藏按钮实现。新申请、待审核、停用、其他团队账号及伪造角色不能读取。
- 设备、资料、成员、超级管理员保护记录、权限审计、消息、常用应用统计、团队公告及备份记录集合要求 `ADMINONLY`，客户端通过云函数访问。
- 首页待办只返回当前账号有权审批的真实申请；公告仅已审核且启用的 IMC 成员可读，管理操作仅超级管理员可用，写入事务内再次校验当前身份和记录版本。撤下的公告不再向成员展示，记录保留用于备份和审计；不自动发送微信消息。
- 移出成员使用 `removed` 状态并清空角色，原子更新超级管理员保护名单、权限审计和本人通知。移出后不能读取成员目录、设备、公告或管理数据；可通过本人资料表单重新申请，但只进入无角色、无权限的 `pending`，需管理员重新审核，旧角色不会自动恢复。重新申请事务同时增加成员版本、记录审计并创建新的申请通知；保留旧申请、通知已读状态和审批决定，通过申请标识区分各次审核，旧决定不能当作新申请的通过结果。停用状态不能绕过管理员处理。不删除历史业务记录及个人资料，也不能远程擦除此前下载的内容。最后一名超级管理员受服务端保护，不可移出。
- 云存储保留 `PRIVATE`：仅文件创建者及云端管理员可读写。成员头像由已审核的目录接口换取临时链接；已有链接在有效期内可能被转发，停用账号不能立即抹除其已经获得的数据。
- 使用 `node scripts/audit-privacy.cjs` 只读复核上述集合权限、存储安全规则，并验证现有文件的无签名 COS/CDN 链接无法读取、签名链接正常读取。报告不输出签名 URL 或用户资料。
- 此配置不是端到端加密；云账号管理员和获授权的服务端仍可接触业务数据。隐私政策、个人资料删除及云账号多因素认证仍需单独落实，当前并未假装完成。

## 独立加密备份

周报业务集合 `weeklyTemplates`、`weeklyPeriods`、`weeklyReports`、`weeklyVersions`、`weeklyFiles`、`weeklyAudit` 同样为 `ADMINONLY`，文件维持私有。模板编辑仅周报管理员与超级管理员可用，事务内再次鉴权、检查版本；已发布周期固定表单快照。文本统一使用白名单 Delta，禁止任意 HTML、远端图片 URL 或本地图片路径，内嵌图片只保存附件业务 ID。云函数校验当前成员、业务权限、附件所属人、字段和周期、数量/大小、记录版本、截止时间；团队只读权限只得到已提交正文和文件，看不到后续草稿。图片与文档先申请本人暂存路径，再验证文件头、大小和摘要，服务端另存为随机路径的私有原件。提交版本保留正文和原件引用；暂存文件尽力清理，失败不影响已记录原件。临时链接只能在鉴权后生成，链接在有效期内仍可能被转发。提交与催交不会将消息标记为已读。

现有备份工具动态发现新集合及存储文件，因此包含模板、正文、Word/PDF与图片原件、版本和审计。文件型周报最多5个文件；表单每个附件字段最多5个，每个文本框最多10张图片，整份最多50个不同文件，单个5MiB、合计10MiB。增长仍受下面的整体备份容量限制，超过时应使用电脑备份工具或升级备份能力，不能将失败备份当作完整副本。周报按用户明确要求启用 `weeklyPublish` 分钟触发器，仅发布管理员已保存的到期周期；事务内复核权限，重复触发不重复发消息。未创建定时催交、微信后台推送或自动备份任务。

日常入口为超级管理员的「我的 → 数据与服务 → 数据备份」。设置并确认 12 至 128 字符密码后手动创建，完成后依次「下载备份」「导出备份」，由微信原生文件导出界面选择保存位置或联系人。**只有把文件另存到手机/电脑等云环境之外，才形成独立副本；仅创建云端备份不能抵御整个云环境销毁。**请另行保管密码，密码不写入数据库、日志或本机缓存，丢失后无法恢复该文件。

`adminData` 每个状态查询、创建及分块下载请求都校验当前微信身份为已审核、启用的 IMC 超级管理员，不能依赖入口隐藏。备份记录使用 `adminBackups`（`ADMINONLY`），加密文件在私有 `admin-backups/` 前缀，客户端只能按已校验记录下载，不接收任意文件 ID。备份只由用户点击触发，不创建后台定时触发器。

小程序导出包含业务数据库、文件原件、索引、权限及环境信息；项目代码继续由本机管理工具保存。导出会跳过备份记录集合与旧备份文件，避免递归备份。采用双读稳定性校验、gzip、scrypt 和 AES-256-GCM；单个附件上限 8 MiB、备份原始 JSON 上限 32 MiB，超出时明确失败，使用电脑工具处理。成功创建与成功导出分开显示，不能把云端创建成功视为已保存在电脑。

手机导出 `.imcbak` 文件后，可在电脑运行：

- `node scripts/restore-app-backup.cjs verify "备份文件.imcbak"`
- `node scripts/restore-app-backup.cjs extract "备份文件.imcbak" "新的恢复目录"`

终端会隐藏输入密码，认证并校验完整包后才写出资料。只恢复到不存在的新目录，不覆盖线上数据。此格式与下面的本机管理工具备份格式分开识别，不共用本机密钥。

### 电脑管理工具

运行 `node scripts/backup-imc.cjs`。

- 默认位置：`D:\Study\IMC-backups`，在项目和腾讯云环境之外；可通过 `IMC_BACKUP_DIR` 指定其他本地目录或已挂载 NAS。
- 密钥：`%LOCALAPPDATA%\IMC\backup-keys\imc-data.key`，与备份目录分开放置。首次生成随机 256 位密钥，绝不写入 Git、终端或聊天。Windows 目录关闭权限继承并授予当前用户与 SYSTEM 访问权；本机管理员仍可能访问，不提供对本机管理员的隔离保证。
- 每个数据库导出、云文件、项目源文件及清单分别用 AES-256-GCM 加密，并记录原始字节数和 SHA-256。文档保留 CLI 返回的 Extended JSON 类型，不将日期强行变成普通字符串。
- 动态发现并备份业务文档集合，而非只备份设备表；同时保存集合权限与索引信息、云存储文件原件、权限规则、环境信息、计费状态、项目代码及部署配置。排除导出备份记录及旧备份文件，避免递归；排除 `.local`、Git、依赖目录和本机私有配置，不复制 CLI 登录凭据或备份密钥。
- 数据和文件清单结束时重新读取并比较；检测到变动、引用文件缺失、下载不完整或校验失败，本次失败，不生成 `verified.json`。这是一份双读稳定性检查的逻辑导出，**不是跨集合事务快照**。重要批量操作期间应暂停写入后再备份。
- 只将通过完整解密和校验的目录标为成功。失败目录可能留下加密的部分文件，不能当作成功备份。暂不自动删除历史版本。
- 当前工具单文件上限 64 MiB、单份内容上限 256 MiB；超过时明确失败，需要升级为流式备份，不能漏文件后仍报告成功。
- 备份读取会消耗云资源和下载流量；未开通额外收费服务，未修改自动续费。

**必须把密钥另存一份到实验室安全保管的离线介质，勿与备份放在同一公开共享位置。**密钥丢失后无法解密；只有本机这一个备份也无法抵御本机硬盘损坏。实验室 NAS 或移动硬盘应再留一份加密副本。

## 恢复与演练

验证：`node scripts/restore-imc.cjs verify "备份目录"`

解密恢复到一个不存在的新目录：`node scripts/restore-imc.cjs extract "备份目录" "新的恢复目录"`

命令先认证并校验所有文件，再写出明文；拒绝已有输出目录、路径穿越、错误密钥、损坏和缺失文件。输出目录同样限制本机访问权，**不会覆盖、删除或写入线上数据库**。

备份根目录 `_recovery-tools` 保存无需项目依赖的恢复程序，即使原项目目录丢失，安装 Node.js 后仍能运行。异机恢复时，通过 `IMC_BACKUP_KEY_FILE` 指向另行保管的原密钥。

恢复结果包括：`database` 文档导出、`storage` 文件、`metadata` 索引/权限/环境信息和 `project` 项目代码。真正迁移到新云环境应先导入测试环境，恢复索引与安全规则，上传文件并按新环境映射 `cloud://` 引用，再验证成员身份、权限、设备数量、消息与附件。文件 ID 与微信 OpenID 受环境及 AppID 约束，不能直接复制地址便宣称迁移完成。恢复工具未实现自动跨云导入或线上回滚。

## 页面实时同步

小程序在前台共用一个原生数据库 `watch`，仅监听 `teamSync/IMC` 的五个随机版本标记：`home`、`messages`、`approvals`、`weekly`、`members`。该文档不包含成员、消息、审批或周报内容。业务数据仍由云函数重新鉴权读取，业务集合保持 `ADMINONLY`。

`teamSyncAccess` 保持 `ADMINONLY`，以服务端取得的微信 OpenID 为键记录本人的成员关联和启用状态，不接受客户端指定身份。首次连接在事务内读取成员并注册关联；成员停用、移出或恢复时，在同一成员事务内撤销或恢复关联。`teamSync` 是唯一使用自定义客户端只读规则的元数据集合：只有关联为已启用 IMC 成员的当前微信身份可以读取 `IMC` 文档，客户端不能写入。规则原文统一保存于 `scripts/lib/sync-rules.cjs`，通过 `scripts/setup-realtime.cjs` 设置，隐私审计逐字验证，备份保存完整规则；不得将业务集合改为客户端可读来实现同步。

成员申请/审批、公告、周报发布/修改/提交/催交和定时发布，与对应版本标记在同一数据库事务中提交或回滚。变更通知仅触发相关缓存失效和可见页面后台读取，不传递业务权限，不标记消息已读，不清空现有列表或覆盖编辑中的表单/上传。离开前台关闭监听；回到前台和断网重连后补读。监听失败期间每5秒轻量查询版本，正常连接每30秒补核版本和成员状态；页面切换复用会话，不逐页重新验证身份。这些是运行期间的连接维护，不新增云端或系统定时任务，也不承诺微信关闭后收到后台通知。

## 页面内到期提醒

入口为超级管理员的「我的 → 数据与服务 → 到期提醒」。云函数通过腾讯云 `DescribeBillingInfo` 查询环境的 `ExpireTime`、套餐与状态，再用服务器时间计算剩余天数，剩余不足一天按一天计算；14 天以内突出显示，过期显示已到期。前端复用最多60秒的本次运行查询结果，返回页面先显示缓存，过期后台重新查询，也可下拉强制刷新。未查询成功时显示失败或未知，不使用硬编码倒计时。续费或发布导致云端日期变化后，下次查询同步更新。

此前创建的 Codex 每日任务已删除。备份和到期提醒没有新增定时任务，也没有自动扣费、续费、微信后台推送或后台备份。页面内到期提醒需要打开页面获取，不承诺应用关闭时仍会通知。周报的定时发布是用户单独授权的云端业务功能，不用于备份或到期提醒。
